# 縦書きリーダー（iPhone / iPad 版）

Windows 版と同じ組版で、iPhone と iPad でも読めるようにしたものです。
App Store を通さず、**Safari で開いてホーム画面に追加する**形（PWA）で使います。

- 縦書き・ルビ・縦中横・禁則処理は Windows 版と同じ処理を移植しています
- ページ境界で文字や画像が切れないよう、行の実測位置でページを割っています
- 小説の見開き、漫画（固定レイアウト）の見開き、進捗バーも同じ動作です
- 本は端末内（IndexedDB）に保存されるので、取り込んだ後は**オフラインで読めます**

**iOS 16.4 以降が必要です。** ZIP の展開に Safari の
`DecompressionStream` を使っているためで、それ以前の iOS では起動時に
その旨を表示して止まります。

---

## 1. どうやって本を入れるか

アプリの「取り込む」を押すと iOS の**「ファイル」アプリ**が開きます。
そこには Dropbox も、Synology Drive（DS124）も場所として並んでいるので、
どちらからでも EPUB を選べます。複数選択もできます。

選んだ EPUB は端末内にコピーされます。以降は Dropbox も DS124 も
起動していなくて構いません。

> ファイル選択に拡張子の絞り込みを付けていません。Dropbox や Synology Drive
> から降りてくる EPUB は種類が正しく付かないことがあり、絞り込むと
> かえって選べなくなるためです。中身が EPUB かどうかは取り込む時に見ています。

## 2. どこに置いて使うか

このアプリは HTML・CSS・JavaScript だけでできています。サーバー側の処理は
一切ありません。**どこかに置いて URL で開ける状態**にするだけです。

### (a) まず試す — PC で動かして Wi-Fi 越しに見る

```bash
python tools/serve.py
```

表示された `http://192.168.x.x:8765/` を iPhone の Safari で開きます。
同じ Wi-Fi にいる間だけ使えます。まず使い勝手を確かめる用です。

### (b) 常用する — GitHub Pages に置く

公開用リポジトリのルートにこのフォルダの中身を置き、リポジトリの
Settings → Pages で「Deploy from a branch」を選ぶだけです。ビルドは要りません。

コピーは手作業ではなく、次で切り出せます（必要なファイルの一覧が
`tools/export.py` に書いてあります）。

```bash
python tools/export.py --out ../epub_reader_web
```

`--runtime-only` を付けると、ブラウザが実際に読むファイルだけになります。

**HTTPS が最初から付くのが最大の利点です。** Safari は暗号化されていない
接続では Service Worker を動かさないため、HTTP だとアプリ本体のオフライン
保存が効きません。また、家の外からでも NAS を公開せずに使えます。

公開されるのはアプリのコードだけで、EPUB も読書位置も端末内から出ません。

### (c) 常用する — DS124（Synology）の Web Station に置く

1. パッケージセンターで **Web Station** をインストール
2. `web` 共有フォルダに `reader` などの名前でフォルダを作る
3. このリポジトリの中身を丸ごとコピー
4. `http://<NAS の名前>/reader/` で開く

DS124 は ARM のため Docker（Container Manager）は使えませんが、
Web Station は静的ファイルを置くだけなので問題なく動きます。

**HTTPS にしておくことを勧めます。** Safari は暗号化されていない接続では
Service Worker を動かさないため、HTTP のままだとアプリ本体のオフライン保存が
効きません（取り込んだ本自体は HTTP でもオフラインで読めます）。
DSM の「コントロールパネル → セキュリティ → 証明書」から Let's Encrypt の
証明書を取れば HTTPS になります。

### (d) 外からも読む

QuickConnect や DDNS で NAS を外に出しているなら、その URL でそのまま使えます。
出したくない場合は、家の中で本を取り込んでおけば外ではオフラインで読めます。

## 3. ホーム画面に追加する

Safari で開いて、共有ボタン → **「ホーム画面に追加」**。
アイコンから起動すると Safari のアドレスバーが消えて全画面になり、
アプリと同じ見た目になります。

## 使い方

| 操作 | 動作 |
|---|---|
| 画面の右 3 割をタップ | 縦書きでは前のページ |
| 画面の左 3 割をタップ | 縦書きでは次のページ |
| 画面の中央をタップ | 上下のバーを出す／隠す |
| 左から右へスワイプ | 次のページ（右綴じの本） |
| 右から左へスワイプ | 前のページ（右綴じの本） |
| 本文中のリンク | 該当箇所へ移動 |

## 本棚

本棚がこのアプリのホームです。起動すると本棚が開き、前に読んでいた本は一番上の
**「続きから」**から一手で戻れます。

- **ジャンル** すべて / 小説 / 漫画 / その他 で絞り込めます。取り込んだ時に
  固定レイアウトなら漫画、それ以外は小説として入り、後から変えられます
- **フォルダ** 「編集」→「＋ フォルダ」で作ります。入れ子にもできます。
  フォルダを消しても中の本は残り、一つ上に移ります
- **並べ替え** 「編集」中に各本の ◀ ▶ で入れ替えます。同じシリーズを
  並べたい時に使います
- **1 冊ごとの設定** 「編集」中の「…」、または本を長押しすると、ジャンル・
  フォルダ・並び・削除がまとめて出ます

## 読む

スワイプは、紙の本をめくる手の動きに合わせてあります。右綴じの本では次の
ページが左側にあるので、それを持ち上げて右へ送る形です。左綴じの本では
すべて左右が入れ替わります（タップの位置と同じ考え方です）。

ページが変わるのは、指が**画面幅の 3 分の 1 ほど**動いてからです。紙が指の
下でたわみ、動かした距離の半ばを過ぎたあたりで送られる感覚に合わせています。
固定の px 値ではなく画面幅に対する割合なので、iPhone と iPad で同じ感覚に
なります。表示設定の「スワイプの深さ」で浅め・ふつう・深めを選べます。

上のバーに「本棚・目次・表示設定」、下のバーに「自動 / 単ページ / 見開き」、
見開きを 1 ページずらす ◀ ▶、進捗バーがあります。
右綴じの本では進捗バーも右から左に進みます。

表示設定で変えられるもの：書体、文字の大きさ、文字の太さ（と微調整）、行間、
字間、上下左右の余白、組方向、見開きの溝、背景色、文字色、背景画像、
漫画の表示方法と背景色。

## Windows 版との違い

| | Windows 版 | iPhone / iPad 版 |
|---|---|---|
| 本の置き場所 | ファイルをそのまま開く | 端末内に取り込む |
| ZIP の展開 | Python の zipfile | ブラウザの `DecompressionStream` |
| 章の読み込み | 独自の `epub://` スキーム | Blob URL に書き換え |
| フォント | PC に入っている全書体 | iOS 内蔵の書体 |
| 全画面 | F11 / ESC | ホーム画面から起動すれば常に全画面 |

組版そのもの（ページ分割、見開き、クリップ、進捗）は同じ実装を移してあります。

**ひとつだけ Windows 版と違う修正が入っています。** 章の一行目にルビが付いていると、
ルビは文字の右側に置かれるため、ページの右端からわずかにはみ出して切れます。
iPhone 版では本文の先頭にルビ 1 つ分の隙間を入れて避けています
（`reader.css` の `html.rd-v > body::before`）。同じ修正は Windows 版にも
入れられます。

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み |
| `app.css` | アプリ側の見た目（セーフエリア対応） |
| `reader.css` | 本文の組版（章の中に注入される） |
| `js/zip.js` | ZIP の読み出し（依存なし） |
| `js/epub.js` | EPUB の解析（Windows 版 `epubfile.py` の移植） |
| `js/resources.js` | 章と画像を Blob URL に変換 |
| `js/reader.js` | 組版・ページ分割・見開き |
| `js/book.js` | spine の進行・口絵の見開き・進捗 |
| `js/library.js` | 本棚と読書位置の保存（IndexedDB） |
| `js/app.js` | 画面の配線 |
| `sw.js` | アプリ本体のオフライン保存 |

### なぜ Service Worker で本を配らないのか

普通なら Service Worker で `epub://` の代わりをさせるところですが、iOS は
ホーム画面から起動したアプリの Service Worker を随時止めます。章の途中で
挿絵が取れなくなる方が、開くのに一瞬待たされるより困るので、章と画像は
あらかじめ Blob URL に変換しています。Blob で作った文書は作った側と同じ
オリジンになるため、iframe の中を計測して組版する処理もそのまま使えます。

## 確認用の道具（`tools/`）

| コマンド | 何をするか |
|---|---|
| `python tools/serve.py --books <フォルダ>` | 動作確認用のサーバー |
| `python tools/ui_test.py --book <一部>` | タップ・リンク・目次・見開き・設定・位置保存の通し確認 |
| `python tools/shot_web.py --book <一部> --out x.png` | 実際の表示を画像に取る |
| `python tools/make_icons.py` | ホーム画面のアイコンを描く |
| `tools/harness.js` | ブラウザから流す一括検査（文字切れ・リンク） |

`harness.js` の文字切れ検査は、組版側の計算を使わずに、画面に出ている
クリップ範囲と行の実測位置だけで判定します。組版側の理屈を借りると
「自分が正しいと思っている」ことしか確かめられないためです。
